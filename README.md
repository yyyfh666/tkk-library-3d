# 嘉庚图书馆 · 3D 数字展馆

网页版 3D 场景：一座悬浮岛上的嘉庚学院图书馆 + 走进去的**三楼大厅**（挑空三层、第一视角可漫游）。
参考的是"成都 3D 微缩城市（CHENGDU IN MINIATURE）"那类展示页的做法。

**全部内容由代码程序化生成** —— 没有任何外部模型或贴图文件（砖、木、灰泥、水磨石、吊顶、
叶片都是 canvas 现画的），改一个数字就能改形体。大厅形体的对标依据是本仓库的
`参考资料/实拍照片/`（12 张实拍，2026-10-13 收到）。

```bash
npm install
npm run dev      # 浏览器打开终端里提示的地址
npm run build    # 打包到 dist/
```

## 场景里有什么

**悬浮岛（默认场景）**：图书馆主楼（白墙 / 闽南红瓦 / 中央蓝玻璃天窗 / 正南入口柱廊）、
西侧柱廊辅楼、楼前石板广场与喷水池、嘉庚式白石牌坊、东侧浅湖、成簇的棕榈与阔叶树、
路灯、长椅、散布的小人、几块飘着的小岩块。

**三楼大厅**（点"走进大厅"→ 再点"第一视角漫游"）—— 按实拍照片重建的真实米制室内：

- **红砖墩柱**（花岗岩柱基与压顶）与**白色凹槽圆柱**上下对位，贯穿三层
- **挑空回廊**：黑钢密杆栏杆 + 木扶手，廊边垂吊绿植成串（照片里最抓人的一笔）
- 两侧翼**对称双跑楼梯**（踏步 0.15m，黑钢扶手，0→1→2 层贯通），中庭南缘的**层叠看台**
  （花岗岩，一级级能走上去，顶上安着深色根雕）
- **深胡桃木书架**书巷（黑钢架 + 书脊白标条），北墙一段**红砖展墙**
- 白瓷砖**黑镶边地面**（每 2.4m 一格）、白色格栅**吊顶**（筒灯 + 灯带）、窗外树影
- 阅览桌椅、借还服务台、VR 阅读区、巡游的导览机器人
- **导览机器人**：绕中庭巡航；在右栏"导览台"搜书名 → 它用 **A\* 寻路**走到那排书架前
  （导航栅格是"障碍膨胀 + 拉绳平滑"，寻路只在收到命令时跑一次，帧循环里只剩路点跟随），
  到达后弹书卡，书架屏同步翻到那本书；另有"签到打卡"一键派它去中庭打卡点
- **陈嘉庚全息演讲**（一场完整的演出）：北墙展区前的花岗岩基座，走近 5m 自动开场 ——
  画面从一团晃动的光晕**收拢成实体**（进场虚化），Shader 同时做色差、扫描线、上扫光带、
  边缘描边与能量闪烁（含偶发的"掉帧暗带"）。面板上一章一张 1024×768 的 alpha 剪影图
  （台阶 + 演讲者 + 台下学子的背影 + 章节背景），**几何体一个都不加**。
  进入观看态后常规漫游 UI 整层收掉，改成上下黑边 + 底部字幕 + 左侧可点的时间轴
  （1913 集美小学 → 1918 集美学校 → 1921 创办厦门大学 → 1923—1933 集美学村 → 1939 南侨机工）；
  点节点换章节 = 换一张贴图 + 换字幕 + 换旁白。此间**锁走路、不锁转头**（镜头会先平滑转过来），
  Esc / 点"退出观看" / 走出 8m 三者任一退场，投影缓缓消散、恢复漫游
- **书架智能显示屏**：一层书架的层板侧面贴着 CanvasTexture 小屏，显示架号与在馆情况；
  鼠标（俯视）或准星（第一视角）指着书脊时，屏幕翻到那本书（封面块 / 书名 / 索书号 / 在馆状态），
  并在 3D 里给那本书套一个高亮框
- **VR 沉浸阅读舱**：走进西侧 VR 阅读区的地毯，墙上幕布就亮起来"放映"一页馆藏导读 ——
  页眉页脚、左图右文都是**运行时用 canvas 现画**再贴上去的（一张外部图片都没有），
  插图（海底分层 / 黑烟囱 / 学村轮廓 / 红砖拼花…）也是现画的；右栏卡片可换书、翻页，
  第一视角下还能用 ← → 翻。翻页 = 重画一张 1024×576 + 换页时先淡下去再涨回来

**第一视角**：鼠标锁视 + WASD（Shift 加速）。能上楼梯、看台上、回廊里走，撞得到墙/柱/栏杆/书架
（沿着墙滑），站上回廊栏杆边不会掉下去；准星指着热点会提示"按 E 查看"，
盯着书脊还能把那本书的馆藏翻到旁边的书架屏上。

**昼夜**：右上角切换。夜里吊顶灯带 + 4 盏暖色点光（"馆灯初上"）、窗玻璃整片点亮、
页面底色从米白切到深蓝 —— 页面底色和 3D 场景背景是同一个颜色，这是参考图那种
"模型浮在一整块色上"的关键。

## ⚠️ 交出去之前必须知道的五件事

1. **大厅内部是按实拍照片对标的示意性重建，不是测绘。**
   外形依据那份《三视图线框示意》和外观照片；大厅对照 `参考资料/实拍照片/` 的 12 张手机实拍
   （红砖柱、白墙、挑空回廊、层叠阶梯、深木书架），但**家具布置、展品位置、热点文案都是示意内容**，
   没有图纸。对外别说成"实景还原 / 1:1 复刻"。文案改 `src/scene/hotspots.js`。

2. **仍是"程序化的写实"，不是手工资产的写实。** 照片那种质感来自手工建模与烘焙光照，
   程序化能到的是"形体对、光影对、细节有"，凑近看比不过手工模型。

3. **三个交互里有大量"演示数据"，对外别当资料。**
   书目、索书号、在馆/借出状态（`src/state/mockBooks.js`）是模拟 OPAC 返回结构的**假数据**；
   陈嘉庚的时间轴是常识性史实但**不做史料引用**；全息人像是代码画的**发光剪影**，不是真人影像
   （全息展台与书架屏的**位置也是示意**，没有图纸）。UI 与代码注释里都标了这一点，
   别在对外宣传里把它说成"接入真实馆藏系统"。

4. **全息投影的旁白是浏览器语音合成念我们写的字幕，不是陈嘉庚先生的原声，
   也不是为他克隆的语音。** 仓库里一个音频文件都没有（项目红线是"全程序化、零外部素材"），
   所以只能运行时合成 —— `src/audio/speech.js` 默认用 `speechSynthesis`（普通话）、默认静音。
   接口按 provider 留好了，将来接真实录音或云端语音合成只换 provider，调用方不动。
   另外全息画面上是**示意剪影**，不是他的肖像或任何影像素材。

5. **阅读舱幕布上的文字是我们自写的导读，不是原书原文。**
   `src/state/vrBooks.js` 里只借用了三个馆藏书名（《深海浅说》《南侨回忆录》《闽南红砖建筑》），
   页内文字与 12 张插图全是自己写、自己画的示意内容。对外不能说成"展出馆藏原书"
   或"接入电子书平台"，页面上也留着一行"导读 · 示意内容"。

## 这套 three.js（r186）上踩过的坑，别再踩回去

**通用**
- **`PCFSoftShadowMap` 已被删除**：常量还在、赋值不报错，但渲染器会强制降级成
  `PCFShadowMap` 并打一条 warn。直接用 `PCFShadowMap`。
- **addons 只有具名导出**：`import { OrbitControls } from 'three/addons/controls/OrbitControls.js'`，
  写默认导入会直接报错。
- **`THREE.Clock` 已弃用**，用 `THREE.Timer`（`update()` 之后 `getElapsed()`）。
- **平行光 intensity=1 就是"表面全亮"**（r155 起的物理光照，且没有开关了）：
  sun + hemi + ambient 加起来超过 2，白墙和浅绿会当场过曝成纯白。
  （要判断"会不会爆"的准确红线是 π≈3.14 —— Lambert 的 BRDF 是 albedo/π；2 是保守的工作预算。）
- **`new THREE.Color(undefined)` 不报错，静默给你白色**。少写一个调色板键，场景里就会出现
  一片莫名其妙的白（我们真踩过：树冠全白）。所以 `materials.js` 里加了硬校验，宁可当场炸。
- 开口圆台（湖盆）从上方看到的是**内壁（背面）**，材质得 `DoubleSide`。
- 热点光点要**按距离缩放**，否则镜头一近就变成一个糊在脸上的大橙球。

**阴影（米制小尺度要整套一起改）**
- 平行光的**阴影相机默认只有 ±5**，不设 `shadow.camera` 边界阴影只覆盖中心一小块，改完要手动 `updateProjectionMatrix()`。
- 大厅把 `shadowExtent` 收到 28 后，`shadow.camera.far` 必须同时给（默认 extent*3=84 太近 → 整厅没阴影），
  `normalBias` 要从 0.7 降到 0.03（不然影子整体飘走）。**四个参数是一套，改一个漏三个等于没改。**

**材质与环境反射**
- **`MeshStandardMaterial.envMapIntensity` 默认就是 1**：想"只给表里声明过的材质挂环境反射"时，
  千万不能用 `material.envMapIntensity > 0` 当判据（恒真）——环境会挂到**所有** Standard 材质上，
  每个白面都被环境亮度抬亮，白墙/看台/绿植直接过曝成 255。要在 `userData` 里记下表里声明的值。
- **别用 `scene.environment`**：r186 会拿 `scene.environmentIntensity` 覆盖每个材质的
  `envMapIntensity`（`WebGLRenderer` 里写死的），还会波及场景里所有 Lambert。
  要环境反射就**逐材质挂 `material.envMap`**。
- 颜色图 `colorSpace = SRGBColorSpace`，**凹凸图必须留 NoColorSpace**，否则 gamma 二次污染。
- 吊顶这类"面朝下、收不到太阳"的大面，不补自发光就是一块灰板 —— 室内反光的效果要靠它替。
- **点光近距离亮度 = intensity / d²**（物理单位）：灯装 3m 高时地面最亮 ≈ intensity/9，
  超过 ~1.5 等效全亮就是死白。大厅只放 4 盏，多了帧率真的掉。

**控件与拾取**
- **`OrbitControls.update()` 不检查 `enabled`**：补间飞行期间调它会被**新机位**的
  min/maxDistance 夹住（旧版就带着这个瑕疵）。补间期间用 `camera.lookAt()` 定姿态，
  落地后再把 target 交还。
- 每帧无条件 `controls.update(dt)` 的 world 里，任何"自己写相机"的模式（第一视角）
  **必须跳过这一行**，否则两套输入抢相机。
- `PointerLockControls` 的 `moveForward/moveRight` 读 `camera.matrix`，而 matrix 要等
  `renderer.render()` 才刷新 → 平移方向滞后一帧。第一视角的平移从 `camera.quaternion` 自己算。
- **`Raycaster` 不检查 `visible`**：`visible = false` 的球照样能被命中 —— 第一视角的准星拾取
  就是靠这个做"不可见代理球"。
- `InstancedMesh.setColorAt` 之后要手动 `instanceColor.needsUpdate = true`；
  `instanceColor` 与 `material.color` 是**相乘**的关系（所以书的材质白天必须纯白，
  昼夜压暗才能自动生效）。
- 娃娃屋视角要**按相机方位把近侧的墙藏掉**（`hall.js` 的 `updateWalls`），
  但第一视角下要**锁定**（四面临墙全回来），不然站在屋里的近侧墙会消失。

**机器人寻路**
- **"楼板上的洞"碰撞盒表达不了，必须在导航栅格里显式封。** 一层楼板在中庭处是挖空的
  （`FLOORS.level0` 挖掉 `ATRIUM`），但碰撞箱里没有任何一条能表示"这里的空气不能站"——
  栏杆只围了边，南边还给层叠看台留了缺口。不封的话 A\* 会走最短路直接**穿过中庭**，
  机器人就飘在看台上空。所以 `buildNavGrid` 收了 `blockedRects`，值来自 `hallLayout.js` 的
  `ACCESS.voidRects`。**以后再加地面孔洞/下沉区，记得同步这个表。**
- 给全息展台的碰撞盒**故意比基座高**（0.55 而不是 0.26）：玩家的步高是 0.36，
  矮于步高的盒子会被 `resolveXZ` 当成"可以迈上去的路缘"直接跳过，人就穿进全息面板里了。
- 机器人/玩家共用同一套 `collision.js`，但**落脚点标签不一样**：机器人只看 `groundOnly=false`
  的实体，高度带取 `yMin=0.15 ~ yMax=1.5`（它只有那么高）。

**幕布 / 贴图面板**
- 面板的 x 一定要算在**既有幕布盒子"朝厅那一面"的前面**：盒子中心 `-halfW+0.5`、厚 0.1，
  朝厅面在 `-17.45`，所以 `VR_READ.x = -halfW + 0.62`。差一点点就被盒子挡在里面看不见
  （这种"东西建了但屏幕上没有"的错，纯读代码看不出来）。
- 想要**曲面环幕**的话注意：`CylinderGeometry` 从内侧看（`side: BackSide`）贴图是**水平镜像**的，
  得配 `texture.repeat.x = -1` + `RepeatWrapping` 才能读。这里用了平板 + `rotation.y = π/2`
  （此时画布的 u 轴正好落在观众的右手方向，文字天然不镜像），不为那点弧度去承担镜像风险。
- 透明件（幕布淡入用 `opacity`）要 `depthWrite: false`，否则淡入过程中会和背后的盒子抢 z。
- **右栏卡片变多之后，"跟着相机走"地冒出来的卡很容易落在折叠线以下**（`.hall-rail` 有
  `max-height` + 滚动）。`HallHUD.jsx` 的 `useAutoReveal` 在卡片出现时把它 `scrollIntoView`
  一下 —— 加新卡片时记得挂上，不然功能是好的但用户看不到。

**全息演出态（cinematic）**
- **锁走路千万别用 `walk.setEnabled(false)`**：它会顺带 `pl.unlock()`，指针锁一没，
  界面上就冒出"点击画面继续漫游"，观众还得再点一次才能接着看 —— 很出戏。
  正确做法是 `walkControls` 的 `setMoveLocked(true)`：只把 ix/iz 归零，指针锁和转头都留着。
- **演出期间 Esc 收不到 keydown**：指针锁定时按 Esc 是浏览器自己解锁、不派发给页面。
  所以"退出观看"必须**两条路都接**：keydown 里的 Escape（没锁定/无头环境走这条）
  ＋ `onWalkChange` 里"丢了指针锁且正在演出 → exitHolo()"。少了后者，退出后会立刻被
  判定成"该进演出"而拉回去，来回抽搐。
- 退出后要设 `holoDismissed`：人还站在触发圈里，不记住"他已经不想看了"就会马上被重新接管。
  走出 8m 再回来才重置成"新的一次演出"。
- **store 是静音开关的唯一真相，语音总线得跟着它走**：第一版只改了 store 的
  `holo.muted`，没同步给 `speech.setMuted()`，结果界面上写着"旁白开"、总线上还是静音，
  怎么点都没声（探针就是靠"掐断次数 = 换章次数"把这个抓出来的）。
- 换章必须**先 `cancel()` 再 `speak()`**。连点时间轴节点时，上一句还没念完，不掐就是两条
  声音叠在一起。`speech.say()` 里那一行是唯一防线。
